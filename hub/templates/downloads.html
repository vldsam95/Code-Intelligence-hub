ONE-LINE INSTALL

Install a Worker on a VPS or new computer

  1. For Hub connectivity: create a single-use Host Install Token. Without a Hub, use --local-only.
  2. On the new host: run one command to install the Worker, local MCP and skills together.
  3. In a project: init only after an explicit onboarding request; after cloning, use open.
curl -fsSL {{ base_url }}/downloads/install.sh | sh -s -- \
  --hub {{ base_url }} \
  --install-token <OPTIONAL_INSTALL_TOKEN> \
  --clients codex,claude,hermes

WHAT TO COPY — PROJECT MOVE

Move a project between hosts

Transfer the entire source directory, including these three portable inputs:

.code-intel/
├── project.yaml / policy.yaml / AGENT_POLICY.md
├── SKILL.md / README_AGENT.md
├── context/
├── portability/
└── hub.example.yaml

local/, graph databases, traces, caches and credentials stay outside Git. The Worker rebuilds the graph for the local revision.

WHAT TO GIVE THE AGENT

New host / agent requiring setup guidance

  • A prepared prompt from Prompts & Skills
  • A single-use Host Install Token, only for Hub connectivity
  • If curl is blocked: the complete ZIP
  • The path of the project to enable explicitly
  • A Wiki ID only when a real binding exists

Without a token, the agent installs in local-only mode and all code features remain available. Never send Worker credentials, master keys or owner passwords.

LINUX

Install from a ZIP

sudo ./install-offline.sh \
  --hub {{ base_url }} \
  --install-token '<OPTIONAL_INSTALL_TOKEN>' \
  --clients codex,claude,hermes

WINDOWS

PowerShell + WSL2

.\install-windows-wsl.ps1 `
  -Hub '{{ base_url }}' `
  -InstallToken '<OPTIONAL_INSTALL_TOKEN>' `
  -Clients 'codex,claude,hermes'

Native Windows does not provide Unix sockets/systemd; the script installs the Worker inside WSL2 with systemd.
